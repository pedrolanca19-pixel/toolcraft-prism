## Goal

A `Masks` section where `+` appends a circle mask and `−` removes the last one. Each mask is an ellipse the user can move, resize on two axes, rotate, and soften with its own blur. A `Show masks` switch toggles the authoring view: on, the wave renders unmasked and every mask is drawn over it as a translucent red shape (with its blur visible); off, the wave is visible only inside the union of the masks — the background (or transparency when Background is off) shows everywhere else. Export always applies the masks and never contains the red overlay.

## Product Decision

- One new entity, one section: `id: "masks"`, title `Masks`, placed directly after `Frame` (both describe what part of the output is visible). Two controls: `masks.items` (`collectionActions`) and `masks.preview` (`switch`). No new panels, layers, timeline modes, or custom controls.
- Mask record (`itemControls`, added and removed atomically): `center` — `vector` (screen coordinates, `[-1, 1]` per axis, default `{ x: 0, y: 0 }` = canvas center); `width` — `slider` 2–200 %, default 40; `height` — `slider` 2–200 %, default 40; `rotation` — `slider` −90…90°, default 0; `blur` — `slider` 0–100 %, default 20. Width and height are diameters as a percentage of the canvas short edge, so a fresh mask is a circle; unequal values make an ellipse; rotation turns it. Two sliders instead of a size vector because radii are never negative and the pad's `[-1, 1]` domain would waste half its range.
- Blur is analytic feather, not a blur pass: coverage per mask is `1 − smoothstep(1 − f, 1 + f, d)` where `d` is the distance in the mask's own normalized frame (0 at the center, 1 on the edge) and `f = blur / 100`. Zero blur is a hard edge; 100 % feathers from the center out to twice the radius. Cost is constant per fragment; no framebuffer or Gaussian kernel is involved.
- Union of masks: `coverage = 1 − Π(1 − cᵢ)` — a soft union that never shows seams where two feathered masks overlap. With zero masks `coverage = 1` and the frame is bit-identical to today's output (identity guard in tests).
- Apply point: in `composeDispersionSheet`, immediately before the saturation step, `light *= coverage`. Because `keyed`/alpha derive from `light`, the transparent-background path hides the sheet outside masks automatically, and Background ON shows the background color there. The Frame clip (rect / rounded / circle) still applies afterwards.
- Preview mode is drawn by the same shader branch, not by DOM/SVG: when `uMaskPreview == 1` the light is not multiplied; after the background composite the fragment is tinted `mix(rgb, vec3(0.92, 0.18, 0.18), 0.35 · coverage)` (alpha raised to at least `0.35 · coverage` on the transparent path). This makes the red feather pixel-exact with the applied feather, which is the whole point of the authoring view. The export renderer always passes `maskPreview: false`, so the overlay can never reach an artifact — the "product editing overlay stays out of export" rule is satisfied by construction, and a clean-export proof compares exported artifacts with the switch on and off.
- Coordinates are resolution-independent: the shader works in short-edge units, `p = (uv − center01) · iResolution.xy / min(iResolution.x, iResolution.y)`, with the vector's screen-space Y flipped once for `gl_FragCoord`. Preview at `internalScale` and 8K export therefore place every mask identically (parity proof below).
- Cap: `MAX_MASKS = 12`. Uniform arrays are fixed-size; the normalizer keeps the first twelve records, the control declares `recommendedMaxItems: 12`, and the description states the cap. Twelve also satisfies the performance rule that many-item fixtures apply at least ten real items.
- Interaction ownership (Stage 1 — panel-only, this delivery): `masks-collection-edit` (panel, `collection-edit`, target `masks.items`, evidence `user-request`: masks are added with the plus); `masks-transform-properties` (panel, `property-edit`, target `masks.items`, evidence `usability-analysis`: exact width/height/rotation/blur values and per-mask blur need a panel; alternative canvas rejected because the red preview already gives spatial feedback and a canvas-only transform would hide exact values); `masks-preview-mode` (panel, `property-edit`, target `masks.preview`, evidence `user-request`). Stage 2 (separate follow-up, not in this batch): a canvas handle layer in `canvasContent` that drags `center` and the two radii directly (`direct-spatial-edit`), with `kind: "canvas-handle"` acceptance rows, `interactionId` links on the panel vector as `precise-value-entry`, and `expectExportExcludesCanvasHandles` proof.
- Defaults and persistence: `masks.items` defaults to `[]`, `masks.preview` to `false`, so every existing workspace and settings file renders exactly as before; no persistence version bump. Both targets are ordinary value controls, so localStorage, settings transfer, section reset, global reset, and history cover them for free. Masks are static in the timeline (playback mode; the loop seam is untouched). Keyframing masks is out of scope.

## Risks

- Feather thickness is measured in the mask's normalized frame, so on a strongly elongated ellipse the visible blur is thinner along the short axis than along the long one; acceptable for soft masks, and a true Euclidean feather can replace the distance function later without changing the schema.
- The collection control has no runtime hard cap; masks beyond twelve are silently ignored by the renderer (declared in the description and the normalizer test).
- `masks.preview` persists like any control value, so a workspace saved with the overlay on reopens in authoring view; export is unaffected by design.
- The `[-1, 1]` pad confines centers to the canvas; masks near the edge still extend outside through width/height, which covers edge vignettes.
- Adding the `mask-count` dimension changes the derived performance paths and fixtures; the protected delivery gate re-derives them, so the batch must land as one coherent delivery rather than schema first and renderer later.
